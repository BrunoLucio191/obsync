# Glossary

| Term | Definition |
| --- | --- |
| Awareness | Short-lived Yjs presence state (name, cursor color, cursor position). Broadcast to a room, never persisted |
| Base (merge base) | The last server version of a file a regular user received, stored by `SyncBaseStore`, used as the common ancestor in three-way merges |
| `canWriteGlobal` | Per-connection flag on the backend, `true` only for admins; decides whether Yjs updates from that socket are applied |
| Client id | A random UUID generated by each plugin instance at load (`AuthService.clientId`), sent as `X-ObSync-Client`. Selects the backend queue for the request and becomes `originClientId` on broadcasts |
| Composition root | The one place that constructs every service and wires their dependencies: `backend/main.ts` and `plugin/obSync/src/main.ts` |
| CRDT | Conflict-free replicated data type: a structure where replicas apply edits in any order and still converge. Yjs is a CRDT library |
| Gene (vault gene) | `backend/data/gene.json`, a fingerprint of the vault (generation counter, byte and file counts, last change). Lets the initial download be skipped when nothing changed |
| `KeyedLock` | Lock keyed by a string such as `file:<path>:delete`; two tasks with the same key never run at once |
| Muted path | A path the plugin is writing itself, registered in `PathMuteRegistry` for 2 s so the resulting Obsidian event is not published back |
| `networkDoc` | For regular users, the `Y.Doc` attached to the WebSocket provider, separate from the private editor document. For admins it is the same object as `ydoc` |
| `originClientId` | Client id attached to a `VaultChange`, so the client that caused it can ignore the echo |
| Private mode | What regular users experience: they can edit anything locally, and nothing they write leaves their device |
| Provider | The `WebsocketProvider` from `y-websocket` that carries Yjs sync and awareness |
| Queue (`Queue`) | Runs tasks one at a time, in order, each under the `KeyedLock` of its key. `QueueManager` keeps one per id |
| Room | Everything associated with one note path: on the backend, a `YjsRoom` with one shared `Y.Doc` and all sockets for that note; on the client, the documents and provider for the active note |
| Room message queue | `YjsRoom.messageQueue`, a promise chain that processes a room's incoming messages in order and only after the room has loaded |
| Session | Server-side record in `TokenService.#sessions` that every access token, refresh token and ticket belongs to |
| State vector | Compact Yjs summary of which updates a document has, used to send only what the other side is missing |
| Ticket | Random one-use credential valid for 30 s that authorizes one WebSocket handshake on one channel |
| `VaultChange` | JSON event (`create`, `modify`, `delete`, `rename`) broadcast on `/system` after a successful vault mutation |
| `Y.Doc` / `ydoc` | Yjs container holding the collaborative state of one note |
| `Y.Text` `codemirror` | The shared text inside a `Y.Doc`, bound to the CodeMirror editor |
| `.yjs-state` | Binary file under `backend/data/yjs-state/` holding a note's complete Yjs state |
