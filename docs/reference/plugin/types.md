# Plugin data types

## Authentication

Source: [`plugin/obSync/src/auth/auth.types.ts`](../../../plugin/obSync/src/auth/auth.types.ts)

### `UserRole`

```ts
type UserRole = 'admin' | 'user';
```

### `AuthenticatedUser`

```ts
type AuthenticatedUser = {
	id: number;
	email: string;
	name: string;
	role: UserRole;
	active: boolean;
};
```

This is a profile returned by the backend. The plugin uses it to select client
behavior; it is not proof of authorization by itself.

### `AuthSession`

```ts
type AuthSession = {
	token: string;
	refreshToken: string;
	expiresIn: number;
	user: AuthenticatedUser;
};
```

`expiresIn` is expressed in seconds. The two credentials are transferred into
`SecretStorage`; the complete object is not persisted as plugin JSON.

### `UserActionResult<T>`

```ts
type UserActionResult<T> =
	| { ok: true; value: T }
	| { ok: false; error: string };
```

Check `ok` before accessing `value` or `error`.

### WebSocket objects

```ts
type WebSocketChannel = 'system' | 'yjs';

type WebSocketTicket = {
	ticket: string;
	expiresIn: number;
};
```

## Plugin configuration

Source: [`plugin/obSync/src/config/ObSyncConfig.ts`](../../../plugin/obSync/src/config/ObSyncConfig.ts)

```ts
type ObSyncConfig = {
	backendUrl: string;
	accessTokenExpiresAt: number;
	user: AuthenticatedUser | null;
};
```

`backendUrl` is the last URL saved through **Settings → ObSync → Backend
server URL**; an empty string means no backend is configured yet.
`accessTokenExpiresAt` is an absolute Unix timestamp in milliseconds. See
[Runtime backend endpoint](README.md#runtime-backend-endpoint) for how
`backendUrl` is turned into the actual HTTP and WebSocket URLs the plugin
calls.

## Collaboration

Source: [`plugin/obSync/src/collab/collab.types.ts`](../../../plugin/obSync/src/collab/collab.types.ts)

### `CollaborationUser`

The identity needed to select document ownership and build awareness state.

```ts
type CollaborationUser = {
	name: string;
	email: string;
	role: 'admin' | 'user';
};
```

### `PreparedCollabRoom`

```ts
type PreparedCollabRoom = {
	readonly extension: Extension;
	readonly initialText: string;
	connect(): void;
};
```

The preparation phase restores IndexedDB before the network is enabled. The
caller installs `extension`, restores `initialText`, and finally calls
`connect()`.

### `ActiveRoom`

`ActiveRoom` is the internal state holder for one note. Its important fields
are:

| Field | Purpose |
| --- | --- |
| `ydoc` | Document bound to the editor and local persistence |
| `networkDoc` | Document bound to `WebsocketProvider` |
| `provider` | Yjs WebSocket transport and awareness owner |
| `persistence` | IndexedDB lifecycle handle |
| `remoteClients` | Presence indexed by Yjs client ID |
| `requestWebSocketTicket` | Obtains a new ticket for each connection |
| `closing` | Prevents asynchronous reconnect after disposal |
| `persistenceReady` | Prevents network connection before local restoration |
| `networkEnabled` | Records whether the prepared room may connect |

## VaultChange

Source: [`plugin/obSync/src/vault/VaultChange.ts`](../../../plugin/obSync/src/vault/VaultChange.ts)

```ts
type VaultChange =
	| { type: 'create'; path: string; isFolder: boolean; content: string }
	| { type: 'modify'; path: string; content: string }
	| { type: 'delete'; path: string; isFolder: boolean }
	| {
			type: 'rename';
			oldPath: string;
			newPath: string;
			isFolder: boolean;
	  };
```

Every variant may include `originClientId`. The system channel uses it to avoid
reapplying an event generated by the same plugin instance.
