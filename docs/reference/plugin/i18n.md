# Plugin internationalization

The plugin's UI text goes through [i18next](https://www.i18next.com/),
following Obsidian's own configured display language rather than the
operating system's locale.

Source: [`plugin/obSync/src/i18n`](../../../plugin/obSync/src/i18n/)

## `initI18n()`

```ts
initI18n(): void
```

Source: [`i18n.ts`](../../../plugin/obSync/src/i18n/i18n.ts)

Called once from `ObSync.onload()`, before anything else runs. Reads the
current language through Obsidian's own `moment.locale()` (which Obsidian
keeps in sync with **Settings → General → Language**, independently of the
OS locale) and initializes i18next with that as the active language and
English as the fallback. Both dictionaries are provided inline as plain
objects rather than fetched, so initialization is synchronous and `t()` is
safe to call immediately afterward, including from module-level code that
runs during import.

Only `en` and `pt` are supported today; any other configured language falls
back to `en`.

## `t()`

```ts
t(key: string, vars?: Record<string, unknown>): string
```

Thin wrapper around `i18next.t()`. Every user-facing string in the plugin,
from settings labels to `Notice` text, is looked up through this function
rather than hardcoded, keyed against the dictionaries in
[`locales/en.ts`](../../../plugin/obSync/src/i18n/locales/en.ts) and
[`locales/pt.ts`](../../../plugin/obSync/src/i18n/locales/pt.ts), which are
kept as two flat objects sharing exactly the same set of keys.

## `localizeBackendError()`

```ts
localizeBackendError(reason: unknown, fallback: string): string
```

Source: [`backendErrors.ts`](../../../plugin/obSync/src/i18n/backendErrors.ts)

The backend's user-management and authentication endpoints always respond in
English, but structured failures (a duplicate e-mail, a missing user, an
attempt to demote the last admin) also carry a stable machine-readable
`reason` code alongside that English message. This function maps a
recognized `reason` to a localized string; an unrecognized or missing
`reason` (an ad-hoc validation error with no code) falls back to the
backend's own English `fallback` text as-is, so the UI degrades to English
rather than showing nothing.
